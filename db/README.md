# База данных кинотеатра

СУБД: MySQL 8.0 (Docker, сервис `mysql` в `docker-compose.yml`).

## Состав
| Файл | Назначение |
|---|---|
| `init/01_schema.sql` | DDL: таблицы, ключи, индексы, ограничения |
| `init/02_seed.sql` | Тестовые данные (4 фильма, 2 зала, 39 мест, 8 сеансов, 30 билетов) |
| `query.sql` | Запрос на самый прибыльный фильм |
| `../app/public/cinema.php` | Визуализация: выручка по фильмам, схема зала |

## Запуск
```bash
docker compose -f docker-compose.yml up -d
docker exec -it pspa-mysql mysql -upspa_user -ppspa_password pspa_db < db/query.sql
```
Страница визуализации: http://localhost/cinema.php

Скрипты из `init/` выполняются только при первом старте на пустом томе.
Для повторного применения: `docker compose -f docker-compose.yml down -v`, затем `up -d`.

## Логическая модель
Таблицы: `movie`, `genre`, `movie_genre` (M:N), `hall`, `seat_type`, `seat`,
`screening` (сеанс), `screening_price`, `customer`, `ticket`.

Связи (1:N, если не указано иное):
- `movie` — `screening`, `hall` — `screening`
- `hall` — `seat`, `seat_type` — `seat`
- `screening` — `screening_price` — `seat_type` (цена зависит от сеанса и категории места)
- `screening` — `ticket`, `seat` — `ticket`, `customer` — `ticket`
- `movie` — `genre` через `movie_genre` (M:N)

## Ответы на вопросы задания
**Все ли сеансы и места стоят одинаково?** Нет. Цена хранится в `screening_price`
по паре (сеанс, категория места): вечерний сеанс дороже дневного, VIP дороже обычного места.
Фактическая цена продажи копируется в `ticket.price_paid`, поэтому смена прайса
не меняет выручку по уже проданным билетам.

**Как выглядит схема зала?** Таблица `seat`: зал, номер ряда, номер места, категория.
Пара (зал, ряд, место) уникальна. Схему зала со статусом занятости можно получить
из `seat` и `ticket` (см. `cinema.php`).

## Целостность данных
- `UNIQUE (screening_id, seat_id)` в `ticket`: одно место на сеанс продаётся один раз.
- Составные внешние ключи `(screening_id, hall_id)` и `(seat_id, hall_id)` в `ticket`
  гарантируют, что место принадлежит залу, в котором идёт сеанс.
  Колонка `ticket.hall_id` нужна именно для этого.
- `CHECK`: длительность фильма > 0, номера ряда и места > 0, цены >= 0.
- `UNIQUE (hall_id, starts_at)` в `screening`: два сеанса не начинаются одновременно в одном зале.

## Принятые упрощения
- Пересечение сеансов по времени в одном зале не проверяется (нужен триггер).
- Возвраты билетов не моделируются: каждый билет в `ticket` считается оплаченным.
- Каждый билет привязан к клиенту (`customer_id NOT NULL`).
- Время окончания сеанса не хранится: оно вычисляется как `starts_at + movie.duration_min`.

## Самый прибыльный фильм
Запрос в `query.sql` суммирует `price_paid` по всем билетам каждого фильма
и берёт фильм с наибольшей суммой. На тестовых данных результат:
«Космический рубеж», 6500.00 (11 билетов). Для сравнения, у «Смеха до слёз»
билетов больше (14), но они дешевле, поэтому выручка ниже (3180.00).
